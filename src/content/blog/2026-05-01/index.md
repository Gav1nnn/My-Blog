## 前言

最近在了解大模型和 Agent 开发时，经常会看到一些高频词：神经网络、Transformer、NLP、Embedding、Attention、RAG、Tool Calling 等。

刚开始接触这些概念时，很容易感觉它们混在一起：

- 神经网络和 Transformer 是什么关系？
- NLP 和大语言模型是什么关系？
- Embedding 为什么能做语义检索？
- RAG 为什么适合后端开发者切入？
- Agent 到底比普通聊天机器人多了什么？

这篇文章不是深度学习论文笔记，也不会重点推公式，而是从一个后端开发者的视角，先建立一张比较清晰的知识地图。

我的目标不是自己从零训练一个大模型，而是理解大模型相关技术的基本原理，并知道这些能力如何接入真实的后端系统，例如知识库问答、智能客服、代码助手、业务数据查询 Agent 等。

这篇是整个系列的第一篇，主要解决一个问题：

后端开发者到底应该如何理解 AI、LLM 与 Agent 之间的关系？

## 一、为什么后端开发者也需要了解 AI？

过去后端开发更多关注的是：

- 接口设计；
- 数据库设计；
- 缓存；
- 消息队列；
- 分布式系统；
- 微服务治理；
- 权限控制；
- 日志监控；
- 高并发和稳定性。

这些能力依然非常重要。

但随着大模型应用的发展，很多系统开始出现新的需求：

- 企业知识库问答；
- 智能客服；
- AI 编程助手；
- 自动生成报表；
- 根据自然语言查询业务数据；
- 自动总结会议纪要；
- 让模型调用内部系统完成任务。

这些需求并不是单纯“调一个模型 API”就能完成的。

一个真正可用的 AI 应用，背后仍然离不开后端工程能力：

- 用户系统；
- 权限隔离；
- 文件上传；
- 文档解析；
- 异步任务；
- 数据库存储；
- Redis 缓存；
- MQ 消息队列；
- 接口封装；
- 日志监控；
- 成本统计；
- 服务稳定性保障。

所以，对于后端开发者来说，AI 并不是一个完全陌生的方向。

更准确地说，AI 应用开发是在原有后端工程能力之上，额外接入 LLM、Embedding、RAG、Tool Calling 等能力。

## 二、AI、机器学习、深度学习是什么关系？

可以先从大到小这样理解：
```text
人工智能 AI
 └── 机器学习 Machine Learning
      └── 深度学习 Deep Learning
           ├── 神经网络架构：MLP、CNN、RNN、LSTM、GNN、Transformer 等
           └── 应用方向：NLP、CV、推荐系统、语音识别、多模态等
```
其中：

AI 是最大的概念，目标是让机器具备一定的智能能力；
机器学习 是 AI 的一种实现方式，让模型从数据中学习规律；
深度学习 是机器学习的一个重要分支，核心是多层神经网络；
神经网络 是深度学习中的基础模型结构；
Transformer 是一种非常重要的神经网络架构；
NLP 是自然语言处理，是 AI 的一个重要应用方向；
LLM，也就是大语言模型，通常基于 Transformer 架构，主要处理语言理解和生成任务；
Agent 则是在 LLM 之上，结合记忆、工具调用、任务规划、外部系统执行等能力形成的工程系统。

如果用一句话概括：

Transformer 提供了大语言模型的核心架构，LLM 提供了语言理解和生成能力，而 Agent 则是在 LLM 的基础上接入知识、工具和业务系统，让模型不只是“会聊天”，而是能够“完成任务”。

## 三、神经网络、Transformer、NLP、LLM 是什么关系？

很多人刚开始学习时，容易把这些概念混在一起。

可以这样区分。

### 1. 神经网络是基础模型结构

神经网络是一类通过大量参数进行计算的模型。

它可以用于图像、文本、语音、推荐、风控等各种任务。

### 2. Transformer 是一种神经网络架构

Transformer 是神经网络中的一种重要架构。

它最重要的机制是 Self-Attention，也就是自注意力机制。

现代大语言模型，例如 GPT、LLaMA 等，核心思想都和 Transformer 有关。

### 3. NLP 是一个应用方向

NLP，全称 Natural Language Processing，也就是自然语言处理。

它研究的是如何让计算机理解、处理和生成自然语言。

例如：
- 文本分类；
- 情感分析；
- 机器翻译；
- 文本摘要；
- 问答系统；
- 信息抽取。
### 4. LLM 是基于 Transformer 的大规模语言模型

LLM，全称 Large Language Model，也就是大语言模型。

它通常基于 Transformer 架构，在大规模文本数据上训练，能够完成文本理解、生成、总结、翻译、代码生成等任务。

所以这几个概念的关系可以总结为：

神经网络是一类模型结构
Transformer 是神经网络中的一种重要架构
NLP 是自然语言处理这个应用方向
LLM 是基于 Transformer 的大规模语言模型
四、RAG 和 Agent 为什么适合后端开发者？

如果只是研究模型训练，那更偏算法和研究方向。

但如果是做 RAG 和 Agent，那就非常适合后端开发者。

### 1. RAG 天然需要后端工程能力

RAG，全称 Retrieval-Augmented Generation，中文叫检索增强生成。

它的核心思路是：

用户问题
  ↓
检索相关知识
  ↓
把知识交给大模型
  ↓
模型基于资料生成回答

一个 RAG 系统通常会涉及：

文件上传；
文档解析；
文档切片；
Embedding 生成；
向量数据库；
MySQL 元数据；
Redis 缓存；
MQ 异步任务；
权限隔离；
流式响应；
日志监控。

这些都非常后端。

### 2. Agent 天然需要连接业务系统

Agent 不只是聊天，它要能完成任务。

例如用户说：

帮我查一下上周失败的订单，并总结失败原因。

Agent 需要：

理解用户意图；
判断需要查询订单系统；
调用后端接口；
获取结果；
总结失败原因；
返回自然语言报告。

这背后需要后端提供工具接口、权限校验、执行日志、失败重试和监控能力。

所以 Agent 不是单纯模型能力，而是一个工程系统。

## 五、后端开发者应该重点关注什么？

如果目标是做 AI Agent 应用开发，而不是算法研究，我觉得可以重点关注这些内容。

第一类：模型基础概念

需要知道：

Token 是什么；
Prompt 是什么；
Embedding 是什么；
Attention 是什么；
Transformer 大致解决了什么问题；
训练和推理有什么区别。

这些内容不用一开始就深挖公式，但要建立基本理解。

第二类：RAG 工程链路

需要理解：

文档如何解析；
文档如何切片；
文本如何向量化；
向量如何检索；
如何构造 Prompt；
如何处理流式响应；
如何做权限隔离。

这是后端开发者最适合落地的方向之一。

第三类：Agent 工程能力

需要理解：

Tool Calling；
Memory；
Workflow；
多轮对话状态；
工具权限控制；
任务执行日志；
调用失败重试；
成本和延迟监控。

这些内容会让 AI 应用从 Demo 变成真正可用的系统。

## 总结

对于后端开发者来说，学习 AI 应用开发不一定要从训练模型开始。

更现实的路线是：
```text
理解基础概念
  ↓
做 RAG 知识库
  ↓
接入工具调用
  ↓
加入权限、记忆、工作流和监控
  ↓
形成一个真正可落地的 Agent 系统
```
如果说 LLM 提供了语言理解和生成能力，RAG 提供了外部知识补充能力，Tool Calling 提供了操作外部系统的能力，Memory 提供了长期上下文能力，那么 Agent 就是把这些能力组合起来，完成真实任务的工程系统。

这也是我后续学习和做项目时想重点深入的方向。
