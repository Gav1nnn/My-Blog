不过这篇仍然不是数学推导，也不会深入到论文级别，而是从工程开发者的视角理解：

- 神经网络是什么；

## 一、神经网络是什么？

神经网络是一类受到人脑神经元启发的计算模型。

它的本质可以简单理解为：

通过大量参数，对输入数据进行多层变换，最终得到一个预测结果。

一个最简单的神经网络通常包括：
```text
输入层 → 隐藏层 → 输出层
```
例如，我们想预测一个学生是否会挂科，可以把以下信息作为输入：
```text
出勤率、作业分数、课堂表现、期末考试分数
```
神经网络经过多层计算后，输出一个结果：
```text
挂科概率：0.82
```
在这个过程中，模型会通过训练不断调整内部参数，使得预测结果越来越接近真实结果。

对于工程开发者来说，可以先把神经网络理解成一个“可训练的函数”：
```text
输入数据 → 神经网络函数 → 输出结果
```
普通函数的逻辑通常由程序员手写，而神经网络函数中的大量参数，是通过数据训练出来的。

## 二、神经网络中的几个核心概念
### 1. 输入 Input

输入就是模型接收的数据。

不同任务中的输入形式不同：

- 图像任务：输入是一张图片的像素矩阵；
- 文本任务：输入是一段文字对应的 Token 序列；
- 推荐系统：输入可能是用户特征、物品特征、历史行为；
- 风控系统：输入可能是交易金额、登录 IP、设备信息等。

对于大语言模型来说，用户输入的自然语言会先被切分成 Token，然后再转成模型可以计算的向量。

### 2. 参数 Parameter

参数是神经网络真正“学习”的东西。

模型训练的过程，本质上就是不断调整参数，让模型从数据中总结规律。

我们经常看到一些模型规模的说法，例如：

7B 模型、13B 模型、70B 模型

这里的 B 是 Billion，也就是十亿。7B 模型大约有 70 亿个参数。

一般来说，参数越多，模型的表达能力越强，但这并不代表参数越多一定越好。模型效果还会受到训练数据质量、模型结构、训练方法、对齐方式和推理策略等因素影响。

参数规模变大也会带来明显代价：

- 训练成本更高；
- 推理成本更高；
- 显存占用更大；
- 部署难度更高；
- 响应延迟更难控制。

所以在工程落地时，模型选择不是越大越好，而是要结合业务场景、成本、延迟和效果综合权衡。

### 3. 前向传播 Forward Propagation

前向传播就是数据从输入层一路经过网络，最后得到输出结果的过程。

例如图像分类任务可以理解为：
```text
输入图片 → 提取特征 → 分类判断 → 输出“猫”
```
对于大语言模型来说，可以理解为：
```text
输入 Prompt → 模型计算上下文表示 → 预测下一个 Token
```
也就是说，当我们调用一个大模型 API 时，模型正在根据输入上下文进行一次推理计算。

### 4. 损失函数 Loss Function

损失函数用于衡量模型预测结果和真实答案之间的差距。

比如真实标签是“猫”，模型却预测成“狗”，损失就会比较大。

训练的目标就是让损失尽可能小。

可以简单理解为：

预测结果和真实答案差得越远，损失越大；
预测结果和真实答案越接近，损失越小。
### 5. 反向传播 Back Propagation

反向传播是神经网络训练的核心算法之一。

它会根据损失函数的结果，反向计算每个参数对错误的影响，然后调整参数。

简单理解就是：
```text
预测错了 → 找出哪些参数导致错 → 调整这些参数 → 下次预测更准
```
对于我们做应用开发来说，不一定要手写反向传播，但要知道：模型之所以能“学会”东西，背后就是通过大量样本不断进行这样的参数调整。

### 6. 训练与推理

训练和推理是两个不同阶段。

训练 Training：

用大量数据调整模型参数

推理 Inference：

模型参数已经固定，输入新数据后生成结果

对于后端开发者来说，我们大多数时候接触的是推理阶段。

例如：

- 调用 OpenAI API；
- 调用本地 Ollama 模型；
- 调用 Embedding 模型生成向量；
- 调用多模态模型分析图片；
- 在业务系统中接入智能客服或知识库问答。

这些本质上都是在使用已经训练好的模型进行推理。

## 三、常见神经网络类型

神经网络并不是只有一种结构。不同任务通常会使用不同的网络架构。

对于 Agent 开发来说，不需要一开始把所有网络都学得很深，但至少要知道它们分别解决什么问题。

### 1. 前馈神经网络 MLP

MLP，也叫多层感知机，是最基础的神经网络。

它的结构非常直接：
```text
输入层 → 若干隐藏层 → 输出层
```
数据只会从前向后流动，没有循环结构。

它适合处理一些基础分类和回归问题，例如：

- 判断用户是否流失；
- 预测房价；
- 判断交易是否异常；
- 根据特征做分类。

MLP 是理解其他复杂神经网络的基础。

### 2. 卷积神经网络 CNN

CNN 主要用于图像处理。

它擅长从图片中提取局部特征，例如边缘、纹理、形状和局部区域模式。

典型应用包括：

- 图片分类；
- 人脸识别；
- 目标检测；
- 医学影像分析；
- 自动驾驶视觉感知。

可以这样理解 CNN 的工作过程：

底层识别边缘和颜色
中层识别眼睛、鼻子、轮廓
高层识别猫脸、汽车、行人等对象

如果主要方向是 Agent 后端开发，CNN 不需要作为第一优先级深入学习，但要知道它是图像领域非常经典的神经网络。

### 3. 循环神经网络 RNN

RNN 主要用于处理序列数据。

序列数据包括文本、语音、时间序列、日志序列和用户行为序列。

RNN 的特点是：

当前时刻的输出会受到之前状态的影响。

例如输入一句话：

我今天很开心，因为……

模型需要记住前面的“开心”，才能更好地预测后续内容。

但普通 RNN 有明显缺点：

- 长文本容易遗忘前文；
- 训练慢；
- 难以并行；
- 容易出现梯度消失问题。

因此，后来出现了 LSTM 和 GRU。

### 4. LSTM / GRU

LSTM 和 GRU 是 RNN 的改进版本。

它们解决的核心问题是：

普通 RNN 难以记住较长距离的信息。

LSTM 中引入了“门控机制”，包括遗忘门、输入门和输出门。

这些门可以控制哪些信息应该保留，哪些信息应该忘掉。

在 Transformer 出现之前，LSTM 曾经是 NLP 领域非常重要的模型结构，常用于机器翻译、文本分类、语音识别和序列预测。

现在 NLP 主流模型基本已经被 Transformer 取代，但理解 RNN/LSTM 有助于理解 Transformer 为什么重要。

### 5. 自编码器 AutoEncoder

自编码器的目标是：

把数据压缩成一个低维表示，再尽可能还原原始数据。

结构可以理解为：
```text
输入 → 编码器 Encoder → 压缩表示 → 解码器 Decoder → 输出
```
它常用于：

- 数据降维；
- 去噪；
- 异常检测；
- 特征学习。

比如输入一张带噪声的图片，AutoEncoder 可以学习如何还原出更干净的图片。

从工程角度看，自编码器和 Embedding 有一定相似思想：都是把复杂数据压缩为某种有意义的表示。

### 6. 生成对抗网络 GAN

GAN 由两个网络组成：

生成器 Generator
判别器 Discriminator

它们之间是对抗关系。

生成器负责伪造数据，例如生成一张图片；判别器负责判断这张图片是真的还是假的。

两者不断博弈，最终生成器可以生成越来越真实的数据。

GAN 常用于图像生成、图像修复、风格迁移和超分辨率。

### 7. 图神经网络 GNN

GNN 用于处理图结构数据。

图结构由节点和边组成，例如：
```text
用户 A —— 用户 B —— 用户 C
```
典型场景包括：

- 社交网络；
- 知识图谱；
- 推荐系统；
- 风控关系网络；
- 分子结构预测；
- 服务调用拓扑分析。

GNN 会让节点吸收邻居节点的信息，从而更新自己的表示。

例如在风控系统中，如果一个账号和大量异常账号存在关联，那么它的风险评分可能也会升高。

### 8. Transformer

Transformer 也是一种神经网络架构，但它的重要性非常高。

现代大语言模型，如 GPT 系列、LLaMA 系列等，核心思想都与 Transformer 有关。

Transformer 最重要的机制是：

Self-Attention 自注意力机制

它让模型在处理一个 Token 时，可以关注上下文中的其他 Token，从而理解更复杂的语义关系。

对于 Agent 开发来说，Transformer 是最应该重点理解的神经网络架构。

## 四、Transformer 解决了什么问题？

在 Transformer 出现之前，NLP 中经常使用 RNN、LSTM 处理文本。

但它们有几个问题：

长文本信息容易丢失；
训练很难并行；
捕捉远距离依赖的能力有限。

比如这句话：

虽然这部电影的前半段节奏很慢，人物关系也比较混乱，
但后半段的反转非常精彩，所以我最终觉得它很好看。

模型要判断这句话的整体情感，不能只看前半段“节奏很慢”“比较混乱”，还要看到后半段“反转非常精彩”“很好看”。

RNN/LSTM 在长文本上容易遗忘前面的信息，而 Transformer 通过 Attention 机制，可以让每个 Token 直接和其他 Token 建立关系。

这就是 Transformer 的强大之处。

## 五、Tokenization：大模型如何读取文本？

大模型并不是直接读取中文或英文句子，而是先把文本切成 Token。

例如：

我喜欢 Go 语言

可能被切成：
```text
["我", "喜欢", "Go", "语言"]
```
英文单词也可能被拆成子词。

例如：

unbelievable

可能被切成：
```text
["un", "believable"]
```
Token 是大模型处理文本的基本单位。

这对工程开发很重要，因为：

- 上下文窗口按 Token 计算；
- API 计费通常按 Token 计算；
- Prompt 太长会导致成本和延迟上升；
- RAG 拼接文档时要控制 Token 数量；
- 流式输出时，本质上也是一个个 Token 逐步生成。

所以在做 AI 应用时，Token 不只是算法概念，也直接影响系统成本和用户体验。

## 六、Embedding：把文本变成向量

Token 本身是离散符号，模型无法直接理解它们的语义。

因此，需要把 Token 转成向量，这个过程叫 Embedding。

例如：
```text
"猫"  → [0.12, -0.33, 0.88, ...]
"狗"  → [0.10, -0.30, 0.81, ...]
"汽车" → [-0.72, 0.44, 0.13, ...]
```
在向量空间中，语义相近的词，向量距离通常也更近。

比如：
```text
猫 和 狗 更接近
猫 和 汽车 更远
```
这就是语义搜索、RAG、推荐系统中向量检索的基础。

对于 Agent 项目来说，Embedding 非常关键，因为知识库问答通常要经历：
```text
文档 → 切片 → 生成 Embedding → 存入向量数据库
用户问题 → 生成 Embedding → 相似度检索 → 召回相关片段
```
如果没有 Embedding，系统更多只能依赖关键词匹配，很难理解“意思相近但说法不同”的问题。

例如用户问：

Go 协程为什么比线程轻量？

文档中写的是：

Goroutine 的初始栈更小，并且由 Go runtime 调度。

虽然用户没有直接说“Goroutine 初始栈”或“runtime 调度”，但向量检索仍有机会把相关内容召回。

## 七、Position Encoding：为什么模型需要位置信息？

Transformer 本身不像 RNN 那样天然按顺序处理文本。

如果只看 Token，不加入位置信息，模型无法区分：

小明喜欢小红

和：

小红喜欢小明

这两句话包含的词一样，但顺序不同，含义完全不同。

因此，Transformer 需要位置编码，让模型知道每个 Token 在句子中的位置。

位置编码可以理解为：
```text
Token 表示 = 词语语义信息 + 位置信息
```
这样模型才能理解句子顺序。

## 八、Attention 与 Self-Attention

Attention 可以理解为：

当前 Token 在理解自己时，应该重点关注上下文中的哪些 Token。

举个例子：

小明把书放进书包，因为它很重。

这里“它”更可能指的是“书”，而不是“书包”。

模型要理解“它”，就需要关注前面的“书”。

Attention 会给上下文中的不同 Token 分配不同权重，例如：
```text
小明：0.05
书：0.75
书包：0.20
```
权重越高，说明当前 Token 越应该关注它。

这就是 Attention 的直观含义。

它解决的核心问题是：

让模型在处理一个词时，不是孤立地看这个词，而是动态地判断上下文中哪些信息更重要。

Self-Attention 指的是：

同一个序列内部的 Token 之间相互计算注意力关系。

例如一句话中，每个词都可以关注其他词。

它的优势是：

可以捕捉远距离依赖；
不需要像 RNN 那样一步步处理；
适合并行计算；
可以建模复杂上下文关系。

这也是 Transformer 能够扩展到大模型的重要原因。

## 九、Multi-Head Attention 是什么？

Multi-Head Attention，即多头注意力。

它的思想是：

不只从一个角度理解上下文，而是从多个角度同时理解。

比如一句话：

苹果发布了新手机，果粉们非常兴奋。

模型可能需要同时关注：

- “苹果”在这里是公司，不是水果；
- “新手机”和“发布”有关；
- “果粉”和“苹果公司”有关；
- “兴奋”表达情绪。

不同 Attention Head 可以关注不同类型的信息。

这让模型可以更丰富地理解文本。

## 十、Encoder、Decoder 与 GPT

原始 Transformer 包括 Encoder 和 Decoder 两部分。

### 1. Encoder

Encoder 负责理解输入。

适合做：

文本分类；
语义表示；
信息抽取；
文本匹配。

典型代表是 BERT。它是 Encoder-only 架构，更擅长文本理解类任务，例如文本分类、语义匹配、信息抽取等。

### 2. Decoder

Decoder 负责生成输出。

适合做：

文本生成；
对话；
代码生成；
自动补全。

GPT 类模型通常是 Decoder-only 架构。

### 3. GPT 的自回归生成

GPT 的自回归生成可以简单理解为：

基于已有上下文，不断预测下一个 Token。

当你给 GPT 一个 Prompt 时，它的大致处理过程是：

接收你提供的文本；
根据已有上下文计算下一个 Token 的概率分布；
根据概率选择一个 Token 输出；
把刚才输出的 Token 拼接回上下文；
继续预测下一个 Token，直到生成结束。

所以，从生成机制上看，GPT 并不是一次性生成完整答案，而是基于已有上下文不断生成下一个 Token。

虽然这个过程本质上是概率建模，但由于模型在大规模语料中学习到了丰富的语言模式、知识关联和推理模式，所以最终表现出了较强的对话、写作、代码生成和任务理解能力。

## 十一、Transformer 的优势与代价

Transformer 的优势包括：

能建模长距离依赖；
并行训练效率高；
表达能力强；
可扩展性好；
非常适合大规模预训练。

但它也有代价。

最典型的是 Attention 的计算复杂度较高。

当上下文长度增加时，Token 之间需要计算关系，计算量和显存占用都会快速增长。

这也是为什么：

上下文窗口越长，成本越高；
长文档问答不能无限拼接全文；
RAG 需要先检索相关片段，再交给模型；
工程上需要控制 Prompt 长度和 Token 数量；
长上下文模型虽然能力更强，但调用成本和延迟也更高。

对于后端开发者来说，这些不是纯算法问题，而是会直接影响接口耗时、系统吞吐、成本控制和用户体验。

## 总结

这篇文章主要梳理了大语言模型背后的一些基础概念。

可以简单总结为：

神经网络：一种可训练的函数
参数：模型真正学习的内容
训练：调整参数的过程
推理：使用训练好的模型生成结果
Token：大模型处理文本的基本单位
Embedding：把文本变成向量表示
Attention：让模型动态关注上下文重点
Transformer：现代大语言模型的核心架构
GPT：基于上下文不断预测下一个 Token 的生成式模型

对于后端开发者来说，这些知识不需要一开始学成算法专家，但需要理解它们和工程系统的关系。
